## Why

Milestones M0–M4 merged the initial v1 feature set of `lineage.nvim`, but `v0.1.0` has not yet been validated on real multi-file repositories under live LSP servers or published to a public GitHub repository with verified prebuilt binaries. Direct codebase auditing also uncovered blocking defects already on `main` (inverted synchronous Phase 1/Phase 2 hover delivery that drops deltas, silent false-safe `NonNull` fallbacks, Focus/Tree projectors mislabeling pure `Unknown` nodes as `[NULL]`, a 300 MB logical cache cap that leaves no OS RSS headroom, double-parsing in `lower_function`, a single-tag `checksums.json` deadlock, and a CI test coupled to `"TBD"` hashes) that must be fixed and verified against release gates `G1`–`G6` before tagging `v0.1.0` or starting post-v1 work (Go adapter / graph exporters).

## What Changes

- **Rust Sidecar Reliability, Soundness, Memory & Observability (`engine/`):**
  - Decouple `lineage/slice` so Phase 1 flushes its response immediately before dispatching Phase 2 onto a dedicated bounded worker pool (non-blocking `try_send`, RAII `finish_query` guard, inline `(query_id, tx)` in `pending_reverse` so cancellation wakes blocked reverse-RPC calls without tripping EWMA); correlate `LspResolveItemResult` back to `LspResolveKind::CallHierarchyIncoming` to project callers into Phase 2 `tree_rows`, and clear `UnknownReason::ExternalUntyped` only when zero `ExternalUntyped` entries remain in `updated_boundaries`.
  - Eliminate silent false-safe `NonNull` fallbacks (`AbsenceValue::bottom()`, missed `lookup_at_pos`, missing SSA values, unresolved `CallTarget::Local`) in favor of explicit `Unknown`/`Unverified` boundaries, fix `is_absent` in `project_focus_spans` and `project_tree_rows` so pure `Unknown` renders `[?]` instead of `[NULL]`, populate 1-hop `FnSummary.param_flow_to_return` across all three lowerers, capture `stats.phase1_ms` after reduction and projections, make pipeline budgets mode-aware (`50ms` hover / `300ms` tree and `from`), pass `&FileSkeleton` into `lower_function` across all 3 adapters, parse nested braced and glob Rust `use` declarations, add `UnknownReason::ExternalUninstalled` to `schema.rs` and `lattice.rs`, and add `SliceStats.uninstalled_external_calls`.
  - Recalibrate Moka logical cache cap to `clamp(3% RAM, 64 MB, 140 MB)` (empirical target for `<= 300 MB` OS RSS), replace the three `Mutex<HashMap>` workspace config caches with `moka::sync::Cache::new(64)`, remove unused `SliceArena`, expose current-PID `StatusResult.rss_bytes`, default `EnvFilter` to `info`, thread `trace_id` into `expand_node`, and emit structured per-query tracing events.
- **Neovim Client, Multi-Client LSP Bridge, UI & Installer (`lua/`, `plugin/`):**
  - Pass `(workspace_root, lsp_client_name)` internally in Rust (`SymbolResolver::resolve_batch`), add `circuit_open_clients` and `max_timeout_ms` to `LspResolveBatchParams` plus `lsp_timeout_ms` to `SliceParams`, forward `circuit_open_clients` in `client.lua`, populate `client_name` on timed-out items in `lsp_compat.lua`, select `lsp_client_name` via capability-aware `lsp_compat.pick_client`, and branch `vim.str_utfindex` on Neovim `0.10` vs `0.11+` (reading unloaded lines from disk without `bufload`).
  - Fix concurrent `ensure_started` via `state.init_waiters` (drained on `initialize`, `stop()`, and early exit), centralize `client.next_query_id()`, add a 100-entry bounded telemetry ring, preserve `card.symbol .. ": "` on unicode hover headers and update `status_badge`/`is_trivial_peek` in `apply_delta`, wire `tree.lua` `on_delta` + query cancellation + capability-checked `lsp_attached`, clear prior buffer extmarks on re-focus/re-pin and cancel active queries in `focus.lua`, glob `<log_path>*` for `rolling::daily` files in `:Lineage log`, and report `engine_tag`/provenance/`rss_bytes`/call-hierarchy capabilities in `:checkhealth lineage` and `:Lineage status`.
  - Migrate all repo references to public `cristianfritis/lineage.nvim`; make `checksums.json` (`version`, `engine_tag`, `repo`, `targets`) the single source of truth shared by `install.lua` and `client.lua`; add `curl`/`wget` timeouts; verify SHA-256 on `already_installed` release binaries (or accept `<dest>.source_build` when `!opts.force`, removing `<dest>.source_build` on verified release install); fall back to `cargo build --release` on HTTP/network download failures writing an empty `<dest>.source_build` marker while aborting with an error on SHA-256 mismatch; match `:Lineage install!` (`sub == "install!"` plus `bang = true` alias for `:Lineage! install`).
- **Two-Layer Dogfooding Verification Harness & Decoupled Release Pipeline (`engine/examples/`, `engine/tests/`, `benchmarks/`, `tests/`, `.github/workflows/`, `scripts/`):**
  - Implement self-hosted Rust Layer 1 harness (`engine/examples/dogfood_gate.rs`, reusing `LanguageAdapter::parse_skeleton` and `xxhash_rust::xxh3::xxh3_64`, parsing `/proc/<pid>/status` `VmHWM`/`VmRSS` on Linux, emitting JSON + stdout summary) invoked by `benchmarks/stage_a_gate.sh` (with `benchmarks/m1_gate.sh` delegating to it) over 4 external commit-SHA-pinned repos (`zod`, `preactjs/preact`, `fastapi`, `ripgrep`) + in-tree `lineage-engine` cached in gitignored `.dogfood-cache/`.
  - Add committed `>= 40` probe golden nullability suite (`engine/tests/golden_nullability.rs`) with positive `Nullable`/`Absent`/`NonNull` assertions + `0 / N` false-safe `NonNull`, headless mock-LSP two-phase integration test (`tests/test_two_phase_lsp.lua`, including cancellation-race check), fixture-isolated `tests/test_install.lua`, and Layer 2 minimal-config live LSP runner/checklist (`tests/dogfood_init.lua`, `docs/verification/stage-a-checklist.md`).
  - Switch `.github/workflows/release.yml` to `engine-v*` tags + `workflow_dispatch` (`dry_run` skipping tag parity, `(ldd "$BIN" 2>&1 || true)` for static musl, native-runner CLI smoke checks, deterministic `checksums.json`, `make_latest: false`), add `scripts/sync_checksums.sh`, add `tags: ["v*"]`, `cargo check --features mimalloc`, and `v*` manifest checks to `ci.yml`, and synchronize `README.md` and `doc/lineage.txt`.

## Capabilities

### New Capabilities
- `dogfooding-verification-harness`: Self-hosted Layer 1 persistent `lineage-engine serve` Rust verification harness over commit-SHA-pinned multi-language repos, committed `>= 40` probe golden soundness suite (`0 / N` false-safe `NonNull` + positive assertions), headless mock-LSP two-phase CI integration test, and Layer 2 minimal-config live LSP sign-off runner/checklist enforcing release gates `G1`–`G6`.

### Modified Capabilities
- `core-ir-and-slicer`: Recalibrated logical LRU cache target (`clamp(3% RAM, 64 MB, 140 MB)`) with `moka::sync::Cache::new(64)` workspace config caches, single-parse `lower_function(..., &FileSkeleton)`, nested braced and glob Rust `use` parsing, mode-aware pipeline budgets (`50ms`/`300ms`), end-to-end `phase1_ms`, `UnknownReason::ExternalUninstalled` in `schema.rs` + `lattice.rs`, 1-hop `param_flow_to_return`, Focus/Tree `is_absent` fix, and elimination of silent `NonNull` fallbacks.
- `hybrid-lsp-protocol`: Dedicated bounded Phase 2 pool flushing Phase 1 before async `lineage/sliceDelta`, inline `(query_id, tx)` reverse-RPC cancellation, Phase 2 `unknown_boundaries` pruning and `CallHierarchyIncoming` index-correlated tree-row projection, multi-client `circuit_open_clients` + `lsp_timeout_ms`/`max_timeout_ms` propagation, Neovim `0.10`/`0.11+` `vim.str_utfindex` conversion without `bufload`, `init_waiters` (drained on stop/exit), centralized `query_id`, `focus.lua` lifecycle fixes, and bounded client telemetry ring.
- `binary-installer`: Single-source `checksums.json` (`engine_tag`, `repo: "cristianfritis/lineage.nvim"`, `targets`) shared by `install.lua` and `client.lua`, `curl`/`wget` timeouts, SHA-verified `already_installed` (or `<dest>.source_build` when `!opts.force`), automatic Cargo fallback on network/HTTP download failure writing empty marker `<dest>.source_build`, and `:Lineage install!` (`sub == "install!"` + `:Lineage! install` alias).
- `release-pipeline-and-docs`: Decoupled `engine-v*` release workflow (`make_latest: false`, `workflow_dispatch` `dry_run`, static-musl-safe `ldd` + native CLI smoke checks, deterministic manifest), `scripts/sync_checksums.sh`, `ci.yml` `tags: ["v*"]` + `mimalloc` check + `v*` pre-tag manifest guard, fixture-isolated `tests/test_install.lua`, and synchronized `README.md`/`doc/lineage.txt`.
- `observability-and-cli`: Default `info` tracing filter with structured per-query events, current-PID `StatusResult.rss_bytes`, rotating log globbing (`<log_path>*`) in `:Lineage log`, and `engine_tag`/provenance/`rss_bytes`/call-hierarchy capability reporting in `:checkhealth lineage` and `:Lineage status`.

## ADDED Requirements

### Requirement: Canonical Pure-Rust ExportGraph IR and 2-Tier Path Sanitization
`engine/src/export/{mod.rs, ir.rs, sanitize.rs}` SHALL convert `(&SliceEnvelope, &ExportOptions)` deterministically with zero new Cargo crates (`BTreeMap`/sorted `Vec` only, stripping volatile `query_id`, `trace_id`, `phase1_ms`, `phase2_ms`), SHALL normalize edges into top-to-bottom causal orientation (`origin -> consumer`) preserving `direction`, canonical `root_ids`, and `NodePartition` (`Upstream | Focal | Downstream`) using `FlowEdge.edge_side` on `Both` slices (with provenance fallback only on legacy `--from-envelope` JSON), SHALL separate SCC membership (`cycle_group_id` from `scc::tarjan_scc`) from deterministic 3-color DFS feedback back-edges (`is_back_edge`, including self-loops `u == v`) so removing `is_back_edge` always yields a DAG, SHALL merge parallel `(from, to)` edges, SHALL preserve full causal paths under `null_only = true`, SHALL enforce `max_nodes = 200`, `max_edges = 800`, and `max_label_chars = 256` via deterministic BFS priority pruning from `root_ids` recording exact `truncated_nodes`/`truncated_edges`, SHALL assign canonical safe IDs `N0..Nk`, SHALL centralize UTF-8 char-safe `<= 120`-char single-line snippet trimming and `PathSanitizer::scrub_text` in `ir.rs`, SHALL retain full inspector metadata (`file_index`, 0-based `range`, `unknown_reasons`, scrubbed `guard_text`, `danger_kind`, scrubbed `risk_messages`, `provenance`, scrubbed `unknown_boundaries`, `completeness_badges`, and export filter flags `null_only`/`exclude_tests`), and SHALL sanitize all paths via a 2-tier policy (`<workspace-rel>` POSIX paths vs. `<external>/<sanitized-tail>`, stripping `/home/<user>`, `/Users/<user>`, Windows drives, and embedded `file://` URIs across all text fields; `--absolute-paths` allowed on CLI only).

#### Scenario: Path sanitization strips host prefixes and embedded file URIs across all fields
- **WHEN** `ExportGraph` is built for a slice containing workspace files, external files under `/home/alice/.cargo/...`, and a node label or snippet containing `file:///home/alice/repo/src/auth.ts`
- **THEN** workspace files normalize to POSIX relative paths (`src/auth.ts`), external files normalize to `<external>/<sanitized-tail>`, and zero raw `file://` URIs or `/home/alice` prefixes appear in any exported path, label, symbol, snippet, guard, risk message, or unknown boundary

#### Scenario: Causal orientation and separated cycle classification preserve forward cycle flow
- **WHEN** `ExportGraph` is built from a `To` or `Both` slice containing a 3-node cycle `A -> B -> C -> A`
- **THEN** causal edges flow `origin -> consumer` (with `Both` upstream edges feeding `root_ids` and downstream edges leaving `root_ids`), all 3 cycle edges share `cycle_group_id`, only the deterministic DFS feedback edge (`C -> A`) has `is_back_edge = true`, and removing `is_back_edge` edges produces an acyclic DAG

#### Scenario: Null-only filtering preserves connecting causal paths
- **WHEN** `ExportGraph` is built with `null_only = true` on a chain `origin(Absent) -> mid(Nullable) -> guard(NonNull)` and an unrelated branch `const(NonNull) -> other(NonNull)`
- **THEN** the exported graph retains the connecting edges along causal paths reaching or leaving `Absent`/`Nullable` nodes and drops the unrelated `NonNull` branch

### Requirement: Deterministic GitHub-Flavored Mermaid and Unified Graphviz DOT Serializers
`engine/src/export/mermaid.rs` SHALL emit deterministic `flowchart TD` diagrams using flat styled nodes with per-node `file:line` pills (no `subgraph` blocks), safe IDs `N0..Nk`, escaped quoted labels (`"`, `<`, `>`, `::`, `|`, `%%`, `;`, brackets, newlines), Coverage-Honesty 2-axis `classDef` styling and orthogonal badges (`NonNull`, `Nullable`, `Absent`, `Unverified`, `Guard`, `Local Risk`, `Frontier`), dashed cycle back-edges (`-. cycle .->`), completeness header comments, pre-trimmed scrubbed snippets only when `include_snippets == true`, and a 45 KB character ceiling (dropping optional snippets first, then re-pruning via BFS priority with explicit warning). `engine/src/export/dot.rs` SHALL emit deterministic `digraph lineage` (`rankdir=TB`) with `subgraph cluster_f<idx>` file groupings, `\`-first plain quoted escaping, Coverage-Honesty styling, dashed cycle back-edges, clean 0/1-node handling, and byte-identical output across `lineage-engine export --format dot`, `lineage-engine slice --format dot`, and `lineage/export`. Both serializers SHALL render `<= 100`-node slices in `< 50ms`.

#### Scenario: Adversarial identifiers and generics render valid GitHub-flavored Mermaid within 45 KB
- **WHEN** `mermaid.rs` renders a slice containing TypeScript generics `Map<string, Foo | null>`, Rust paths `crate::auth::load`, colons in raw IDs (`caller:1:0`), quotes, `%%`, and newlines
- **THEN** all node IDs are canonical `N0..Nk`, all Mermaid-sensitive characters are escaped cleanly inside quoted labels, output stays `<= 45 KB` (with explicit warning if trimmed/pruned), and rendering completes in `< 50ms`

#### Scenario: CLI and RPC produce byte-identical Mermaid and DOT output
- **WHEN** identical `SliceEnvelope` and `workspace_root` inputs are rendered via `lineage-engine export --format dot`, `lineage-engine slice --format dot`, and NDJSON RPC `lineage/export`
- **THEN** all three produce byte-identical output and valid Graphviz syntax

### Requirement: Bounded 4-Slot Snapshot LRU and Non-Blocking `lineage/export` RPC
`engine/src/protocol/transport.rs` SHALL advertise `EngineCapabilities.export_formats = ["mermaid", "dot"]` under `PROTOCOL_VERSION = 1`, SHALL maintain a mutex-guarded 4-slot `QuerySnapshotCache` LRU keyed by `query_id` (keeping `include_graph = false` on Hover/Tree wire replies) updated in-place by `execute_phase2` and by `lineage/expand` when `parent_query_id`/`parent_node_id` are provided (remapping `file_id`s and namespacing expanded node IDs as `exp{k}_{id}` to prevent collisions), and SHALL implement `"lineage/export"` with tri-state `include_snippets: Option<bool>` (`None => false` uniformly across formats): serving settled LRU hits immediately (`< 50ms`), handling `InFlight` LRU hits without re-slicing or blocking Phase 1 workers, returning immediately on fresh slices when `no_lsp = true` or `phase2_opt` is `None`, and dispatching pending fresh Phase 2 work (`ExportPhase2Job`, `phase2_ceiling_ms = lsp_timeout_ms.unwrap_or(500)` with per-call LSP timeout propagated up to ceiling) onto the dedicated Phase 2 worker pool (falling back cleanly to Phase 1 stamped `Static only (LSP queue full)` if the 64-slot queue is full).

#### Scenario: Exporting from an active Tree snapshot includes Phase 2 and expanded frontiers with zero ID collisions
- **WHEN** a client opens a Tree slice (`include_graph = false`), Phase 2 LSP settles, the user expands a `FrontierNode` via `lineage/expand` with `parent_query_id` and `parent_node_id`, and then calls `lineage/export` with that `query_id`
- **THEN** `lineage-engine` serves directly from `QuerySnapshotCache` in `< 50ms` (`source_mode = "live_snapshot"`), including Phase 2 edges and collision-free `exp{k}_` expanded nodes

#### Scenario: Fresh export with pending Phase 2 settles on the Phase 2 pool without starving Phase 1
- **WHEN** a client calls `lineage/export` without a cached `query_id` on a buffer with unresolved LSP boundaries and `lsp_timeout_ms = 500`
- **THEN** `transport.rs` dispatches `ExportPhase2Job` onto the Phase 2 worker pool without blocking Phase 1 workers, replies with merged Phase 2 nodes if settled in time, or replies with Phase 1 stamped `Static only (LSP timed out after 500ms)` on timeout (distinct from `Budget-capped (partial)`)
